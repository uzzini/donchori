# Git Commit Command

현재 Git 작업 트리의 변경사항을 분석하고 커밋한다.

## 수행 절차

### 1. 변경사항 확인

아래 명령어를 순서대로 실행하여 변경사항을 확인하고, 변경된 내용을 상세히 검토한다.

git status
git diff

### 2. 변경사항을 분석하고 작업 내용을 요약하여 보고한다.

커밋 전에 아래 형식으로 사용자에게 보여준다.

변경 파일

- src/pages/LoginPage.tsx
- src/styles/tokens.css

변경 요약

- 로그인 페이지 UI 추가
- 로그인 라우트 등록
- 인증 상태 체크 로직 추가

예상 커밋 타입

- feat

### 3. 커밋 타입 판단 기준

feat: 새로운 기능 추가
fix: 버그 수정
refactor: 동작 변경 없이 구조 개선
style: 코드 포맷팅, 세미콜론, 린트 수정
design: UI/스타일 변경
chore: 빌드, 설정, 패키지 관리
docs: 문서 수정

### 4. 커밋 메시지 작성 규칙

- 커밋 메시지는 한국어로 작성한다.
- 한 줄로 작성한다.
- 무엇을 변경했는지 명확하게 작성한다.
- 추상적인 표현은 사용하지 않는다.
- 커밋 메시지는 파일명이 아닌 사용자 관점의 기능 단위로 작성한다.
- Conventional Commit 형식을 따른다.

### 5. 커밋 수행

아래 명령어를 실행한다.

git add .
git commit -m "<생성한 커밋 메시지>"

## 결과 보고

커밋 완료 후 아래 형식으로 보고한다.

커밋 메시지

- feat: 카카오 로그인 기능 구현

결과

- 커밋 완료

## 예외 처리

- 변경사항이 없으면 커밋하지 않는다.
- merge conflict가 존재하면 커밋하지 않는다.

## 중요

- 변경사항을 추측하지 않는다.
- 실제 diff를 기준으로 분석한다.
- 코드의 의도를 파악하여 커밋 메시지를 작성한다.
- Commit만 수행한다.
- Push는 절대 수행하지 않는다.
